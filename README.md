# SmartTech Store

متجر تقني يعمل على GitHub و Vercel فقط، بثلاث لغات (عربي · English · Türkçe)، مع لوحة تحكم عربية تتيح لأي شخص إدارة المنتجات والأسعار والصور بدون فتح الكود.

| الصفحة | العنوان | ملاحظة |
|---|---|---|
| المتجر | `/` | الصفحة الأولى، البحث، الأقسام |
| قسم أو فئة | `/c/<القسم>` | تُبنى على الخادم، تفهرسها جوجل |
| العلامات | `/brands` · `/b/<العلامة>` | صفحة لكل علامة |
| منتج | `/p/<رقم المنتج>` | تظهر بصورتها واسمها وسعرها عند إرسالها على واتساب |
| إتمام الطلب | `/checkout` | السلة ← البيانات ← تأكيد |
| إيصال الطلب | `/o/<الرمز>` | رابط خاص بالزبون، يفتح بلا كلمة مرور، ويعرض حالة الطلب الحالية |
| تتبّع الطلب | `/track` | برقم الطلب + رقم الهاتف، لمن أضاع رابط الإيصال |
| لوحة التحكم | `/admin.html` | بكلمة مرور |

## إدارة المتجر (بدون برمجة)

افتح `/admin.html` وأدخل كلمة مرور المدير.

| ما تريد فعله | الخطوات |
|---|---|
| تعديل اسم أو سعر أو وصف | اضغط على المنتج → عدّل → **حفظ** |
| تغيير صورة منتج | افتح المنتج → **اختيار صورة من الجهاز** → انتظر "تم رفع الصورة" → **حفظ** |
| نفاد الكمية | اضغط زر **متوفر / غير متوفر** أسفل المنتج في القائمة مباشرة |
| إضافة خصم | السعر الجديد في "السعر الحالي" والقديم في "السعر قبل الخصم" (تُحسب النسبة تلقائياً) |
| إضافة منتج | **+ إضافة منتج جديد** |
| نسخ منتج مشابه | افتح منتجاً → **نسخ المنتج** → غيّر ما يلزم → **حفظ** |
| حذف واستعادة | الحذف غير نهائي؛ تجده في "المنتجات المحذوفة" أسفل الصفحة |
| التراجع عن تعديل | **إرجاع المنتج كما كان** (للمنتجات الأصلية) |
| تغيير رقم واتساب أو البريد | تبويب **الإعدادات** — ويوجد زر لتجربة الرقم قبل الحفظ |
| متابعة الطلبات | تبويب **الطلبات** — الجديد أولاً، ولكل طلب صفحته وسجلّه |
| أسعار التوصيل | تبويب **الإعدادات** — سعر لكل محافظة |
| إيقاف الاستقبال مؤقتاً | تبويب **الإعدادات** — **إيقاف الطلبات** مع رسالة تظهر للزبون |

الوصف له ثلاث خانات (عربي · إنجليزي · تركي). إذا تركت خانة فارغة يظهر وصف عام مناسب للقسم بتلك اللغة.
كل تغيير يظهر للزبائن خلال أقل من دقيقة.

**المنتج الجديد يبدأ مسوّدة.** لا يظهر في المتجر حتى تختار **نشر**. هذا مقصود: لو رنّ الهاتف في منتصف
الإدخال، لا يرى الزبون منتجاً ناقصاً.

### الطلبات

الزبون يملأ السلة، ثم `/checkout`: الاسم والهاتف والمحافظة والعنوان. الدفع **عند الاستلام**.
عند الإرسال يأخذ رقم طلب ورابط إيصال خاصاً به (`/o/<الرمز>`) يفتحه في أي وقت بلا كلمة مرور —
الرمز موقَّع، ولا يمكن تخمين طلب غيره.

في تبويب **الطلبات**: الحالة تمشي `جديد ← مؤكَّد ← مجهَّز ← مُرسَل ← مُسلَّم`، ويمكن **الإلغاء**
أو **الإرجاع** في أي مرحلة، وتسجيل الدفع عند الاستلام. كل تغيير يُكتب في سجلّ الطلب باسم من قام به.

واتساب ما زال موجوداً كزر مساعدة، لكنه لم يعد طريق الطلب.

**أجرة التوصيل** تُحسب تلقائياً من تبويب **الإعدادات**: سعر لكل محافظة، و«التوصيل مجاني فوق» مبلغ معيّن.
الزبون يرى الرقم في صفحة الدفع، ويُحفظ مع الطلب. المحافظة التي تُركت فارغة تبقى «يُتفق عليه» كما كانت —
فارغ لا يعني صفراً.

**تتبّع الطلب:** كل تغيير للحالة من تبويب **الطلبات** يظهر فوراً في إيصال الزبون. ومن أضاع الرابط يفتح
`/track` (رابط «تتبّع طلبك» أسفل كل صفحة) ويكتب رقم الطلب ورقم هاتفه. الرد على رقم خطأ وهاتف خطأ واحد،
والمحاولات محدودة، فلا يمكن تخمين طلبات الآخرين.

**الأدوار:** المالك (كل شيء) · الموظف (الطلبات والمخزون) · المحرّر (المنتجات والمحتوى). الصلاحية تُفحص على
الخادم في كل طلب — إخفاء الزر في اللوحة مجاملة لا حماية.

## الإعداد على Vercel (مرة واحدة)

1. اربط المستودع بمشروع على [vercel.com](https://vercel.com).
2. من **Storage** أنشئ **Blob Store** واربطه بالمشروع (يضيف `BLOB_READ_WRITE_TOKEN` تلقائياً).
3. من **Settings → Environment Variables** أضف المتغيرات (القائمة الكاملة مع شرحها في `.env.example`)، وفعّلهما في **Production و Preview و Development**:

   | المتغير | القيمة |
   |---|---|
   | `ADMIN_PASSWORD` | كلمة مرور الدخول للوحة التحكم — اجعلها طويلة (20 حرفاً فأكثر) |
   | `ADMIN_SECRET` | نص عشوائي طويل (40 حرفاً) لتوقيع الجلسات — لا تشاركه مع أحد |

   واختيارياً:

   | المتغير | القيمة |
   |---|---|
   | `SITE_ORIGIN` | عنوان المتجر الكامل عند الانتقال إلى نطاق خاص (مثل `https://smarttech.sy`). بدونه يُستعمل عنوان Vercel |
   | `ORDER_URL_SECRET` | مفتاح توقيع روابط الإيصالات. بدونه يُستعمل `ADMIN_SECRET` — وتغييره يُبطل الروابط القديمة |
   | `RESEND_API_KEY` | لإرسال تأكيد الطلب بالبريد. بدونه لا يُرسَل بريد ويعمل كل شيء آخر كما هو |

4. أعد النشر (Redeploy) — المتغيرات تُقرأ عند بدء التشغيل.

**أمان:** تغيير `ADMIN_PASSWORD` أو `ADMIN_SECRET` ينهي كل الجلسات المفتوحة فوراً. مدة الجلسة 12 ساعة.

### نسخ احتياطي واسترجاع

- مع كل حفظ تُكتب نسخة يومية في Blob باسم `data/store-state.<التاريخ>.json`.
- للرجوع لإصدار سابق من **الكود**: vercel.com → Project → Deployments → اختر نشرة سابقة → ⋯ → **Instant Rollback**.
  (الرجوع يستعيد الكود فقط؛ بيانات المنتجات في Blob لا تتأثر.)

### كيف تُدمج البيانات

`catalog.js` هو الأساس، وفوقه تُطبَّق تعديلات لوحة التحكم المحفوظة في Vercel Blob (`data/store-state.json`): `overrides` تعديلات، `additions` منتجات مضافة، `deleted` منتجات مخفية، `settings` معلومات التواصل.

### تحديث الكتالوج من المورّد

```bash
npm i sharp            # مرة واحدة
node tools/import-supplier.cjs
```
يسحب المنتجات والصور والأوصاف ويحدّث `catalog.js` و `assets/products/` و `assets/details.json`.
تعديلات لوحة التحكم تبقى فوق الكتالوج الجديد ولا تُفقد.

### تعديل النصوص

لا نص مكتوب داخل الكود — كله في القاموس. بعد أي تعديل عليه شغّل:

```bash
npm run build
```
يُعيد توليد `style.css` من الرموز، ويكتب النص العربي داخل `index.html` (حتى يقرأ الزائر صفحة
كاملة قبل أن يصل أي JavaScript)، ويحدّث وسوم محركات البحث وبصمات الملفات.

`node tools/split-i18n.cjs` يعيد توزيع القاموس على ملفاته حسب الصفحة التي تعرضه.
المفتاح الذي تحتاجه أكثر من صفحة يبقى في `i18n.js`.

## التشغيل المحلي

```bash
npm install                 # مرة واحدة
cd tests && npm install     # مرة واحدة (puppeteer-core)
cd .. && npm run build      # بعد أي تعديل على القاموس أو الرموز
npx vercel dev              # لتصفّح المتجر محلياً (يحتاج vercel link و .env.local من .env.example)
```

الخادم المحلي (`tests/server.mjs`) يحاكي Vercel: الملفات الثابتة + دوال `api/` + بديل محلي لـ Blob في مجلد.
لا قاعدة بيانات ولا migrations: البيانات ملفات JSON في Vercel Blob، وكل دالة تقرأ الشكل القديم وتكمله
(مثلاً طلب قديم بلا `delivery.fee` يُعرض «يُتفق عليه»). أي تغيير في الشكل يجب أن يبقى قابلاً لقراءة القديم.

> **Windows:** المستودع يفرض نهايات أسطر LF (`.gitattributes`). إن كان عندك نسخة قديمة مأخوذة بـ
> `core.autocrlf=true` فشغّل `git config core.autocrlf false` ثم أعد استخراج الملفات، وإلا فإن
> `npm run build` يختم بصمات خاطئة ويحجب CSP السكربتات في الإنتاج.

## الاختبارات

```bash
npm run lint          # صياغة كل ملف JS، صحة كل JSON، علامات التعارض، CRLF، محارف bidi
npm run typecheck     # TypeScript checkJs على دوال الخادم api/ و lib/
npm run test:unit     # قواعد الأسعار والتوصيل والمخزون والمدخلات (بلا خادم)
npx playwright test   # E2E: تصفّح ← سلة ← طلب COD ← الأدمن ← التتبّع، والأدمن والصلاحيات
npm test              # الاختبارات التسعة في متصفح حقيقي (أكثر من 10 دقائق)
npm run verify        # كل ما سبق
```

Playwright يستعمل Chrome المثبّت (`channel: "chrome"`) ولا يحمّل متصفحاً، ويشغّل خادمه على المنفذ 3200
بمخزن مؤقت في `tests/.blobstore-e2e` يُمسح كل مرة.

| الاختبار | يفحص |
|---|---|
| `config` | إعدادات Vercel والمسارات وسياسة الأمان وبصمات الملفات |
| `design` | أن الشكل مبني على الرموز: التباين، سلّم الخطوط، حلقة التركيز، مقاسات اللمس |
| `content` | الأقسام والعلامات والأوصاف — لا فئة بلا وصف ولا منتج بلا قسم |
| `lang` | تطابق مفاتيح اللغات الثلاث، **عدم وجود أي نص مكتوب داخل الكود**، ترجمة كل عنصر، عدم تسرّب لغة داخل أخرى |
| `api` | الجلسات والتحقق من المدخلات والحفظ المتزامن ورفع الصور ومنع الوصول غير المصرّح |
| `shop` | سرعة الظهور، ثبات الصفحة أثناء التحميل، اتجاه الأرقام والعربية، لوحة المفاتيح |
| `ui` | العرض والبحث والتصفية والسلة والطلب وصفحة المنتج ولوحة التحكم كاملة |
| `compat` | من 320px إلى 1920px، لغة الجهاز، اللمس ولوحة المفاتيح |
| `smoke` | كل رابط في sitemap يرد 200 ومعه بياناته المنظَّمة؛ كل قسم وعلامة وعيّنة منتجات بثلاث لغات بلا أخطاء؛ المعرض والألوان والفلاتر والبحث |
| `e2e/checkout-tracking` | المسار الكامل للطلب، والتتبّع بهاتف خطأ، وبلا JavaScript، وحدّ المحاولات |
| `e2e/admin-rbac` | لوحة التحكم، CRUD، ومصفوفة صلاحيات تُستخرج من الكود: كل إجراء 401 بلا جلسة و403 لكل دور لا يملكه |
| `unit/pricing` | أجرة التوصيل، الإجمالي والخصم، المخزون، دمج الكتالوج، تنظيف المدخلات والهاتف |

## النشر

1. ادمج الفرع في `main` (أو افتح PR) — Vercel ينشر `main` تلقائياً، وكل فرع آخر يأخذ نشرة Preview.
2. قبل الدمج: `npm run verify` على جهازك.
3. لا خطوة بناء على Vercel (`buildCommand` فارغ عن قصد): الملفات المولَّدة (`style.css`، النصوص، البصمات،
   هاش CSP) تُبنى محلياً بـ `npm run build` وتُرفع مع الكود.
4. بعد النشر افتح `/`، `/p/<منتج>`، `/checkout`، `/track` و`/robots.txt` للتأكد.
5. للتراجع: Deployments → النشرة السابقة → **Instant Rollback** (يرجع الكود فقط؛ بيانات Blob لا تتأثر).

الاختبارات لا تتصل بأي خدمة خارجية ولا تمسّ بيانات المتجر الحقيقية.

## ملاحظات

- الأسعار والصور والأوصاف مستوردة من كتالوج المورّد — راجع الأسعار قبل الإطلاق وتأكد من حقك في استخدام صور المورّد.
- لا يحمّل الموقع أي ملف من خارج GitHub و Vercel (لا خطوط ولا أيقونات خارجية).
- الصفحة الأولى تُحمَّل بـ **58.6 ك.ب** من JavaScript مضغوطاً، بميزانية 60. صفحة المنتج والسلة
  ولوحة التحكم تصل عند فتحها فقط، كلٌّ ومعها نصوصها.
